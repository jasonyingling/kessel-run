Research ─→ Anchor ─→ Ideation ─→ Hook ─→ Architecture ─→ Draft ─→ Personalize ─→ Polish
             │                                                                          │

## Stage Triggers at a Glance

| Stage | Trigger Phrases | Output |
|-------|-----------------|--------|
| **Research** | "research this," "what's out there," "find data on" | Research brief with gaps & angles |
| **Anchor** | "I have an idea," "help me plan," "what angle" | Content anchor (topic, audience, goal, framing) |
| **Ideation** | "help me develop," "what angles," "flesh this out" | Ideation map (thesis, points, stories, evidence) |
| **Hook** | "I need a hook," "how should I open," "help with the opening" | Hook + bridge (multiple variants, scored) |
| **Architecture** | "help me outline," "what structure," "how to organize" | Beat map (section-by-section blueprint) |
| **Draft** | "let's start writing," "draft this," "I'm ready to write" | Section drafts (one at a time, user-edited) |
| **Personalize** | "too generic," "make it sound like me," "add personality" | Authenticity audit + personalization prompts |
| **Polish** | "is this ready," "final review," "quality check" | Scorecard (7 dimensions, fixes for each) |
| **Review** | "is this still accurate," "should I update," "content audit" | Update/retirement recommendations |
| **Repurpose** | "turn into LinkedIn post," "make a thread," "repurpose this" | Adapted content in target format(s) |
| **Analyze** | "how did my post do," "analyze this," "what worked" | Performance analysis + lessons for next content |

## Time Targets (Per Stage)

- **Research**: 20–30 minutes (deep, not time-boxed)
- **Anchor**: ~3 minutes
- **Ideation**: ~5 minutes
- **Hook**: ~3 minutes
- **Architecture**: ~5 minutes
- **Draft**: ~8 minutes (section-by-section)
- **Personalize**: ~3 minutes
- **Polish**: ~4 minutes
- **Review**: 10–15 minutes per piece
- **Repurpose**: 5–10 minutes per format
- **Analyze**: 10–15 minutes

**Total for full pipeline**: ~35 minutes (excluding Research)

## Which Skills Do You Need?

### Creating a new article
Research → Anchor → Ideation → Hook → Architecture → Draft → Personalize → Polish

### Creating a new LinkedIn post
Anchor (quick) → Hook → Draft (abbreviated) → Personalize → Polish

### Creating a new thread
Anchor → Ideation (lightweight) → Hook → Draft (one beat per post) → Personalize

### Creating a newsletter edition
Research (optional) → Anchor → Draft → Personalize → Polish

### Cross-publishing existing content
Repurpose (from published piece)

### Maintaining published content
Review (quarterly or after landscape shifts)

### Learning from published content
Analyze (whenever piece gets engagement data)

## Core Principles Checklist

Before starting any stage:

- [ ] **Do I have the inputs this stage needs?** (Don't start Architecture without a confirmed Hook)
- [ ] **Am I in the right format?** (Threaded LinkedIn post architecture is different from blog post architecture)
- [ ] **Do I have a voice profile?** (Stages 3–7 need this; earlier stages optional)
- [ ] **Will I be editing during this stage?** (Draft is section-by-section; Polish is after all editing is done)

## Most Common Mistakes

**Research**: 
- Going too broad; not enough deep dives
- Not connecting findings to content opportunities

**Anchor**:
- Staying vague; not pushing for specific enough idea
- Not checking goal alignment with publication mission

**Ideation**:
- Generating too many thin points instead of fewer deep ones
- Not grounding claims in specific evidence

**Hook**:
- Choosing a hook that sounds great in isolation but doesn't match the piece
- Creating clickbait that misleads about what the reader will get

**Architecture**:
- Treating all sections the same (no energy flow variation)
- Not planning for the middle-piece energy valley

**Draft**:
- Inventing personal details the user didn't provide
- Writing the full piece at once instead of section-by-section
- Not applying the voice profile

**Personalize**:
- Over-personalizing; forcing personality where it doesn't belong
- Not grounding general claims with specific details

**Polish**:
- Not fixing redundancy before considering a piece ready
- Rewriting instead of providing targeted fixes

## Voice Profile Essentials

When a publication has a voice profile, it includes:

**Patterns** (default ways this publication writes):
- Sentence construction style
- Paragraph length preference
- How it opens sections/arguments

**Anti-patterns** (things this publication never does):
- Specific words to avoid
- Sentence structures that don't fit
- Tone registers that don't belong

**Signature moves** (distinctive tactics):
- Recurring narrative structures
- Specific frameworks or devices
- Recognizable openings or closings

**Reference samples** (published pieces that exemplify the voice):
- Use as calibration standard
- Read them cold before drafting

## Performance Signals to Track (For Analyze Stage)

When content is published, collect:
- **Quantitative**: Views, engagement rate, time on page, completion rate
- **Qualitative**: Comments, DMs, which sections get quoted
- **Comparative**: How this performed vs. your typical numbers
- **Actionable**: "Which section got the most response?" "What did people ask for more of?"

## The Feedback Loop

```
Analyze Stage ─→ Extract Patterns ─→ Inform Next Research
     ↓                                        ↓
Learn which hooks work ──→ Feed into Hook Stage
Learn which topics resonate ──→ Feed into Ideation
Learn audience preferences ──→ Feed into Anchor
```

Each published piece makes the next piece better.
