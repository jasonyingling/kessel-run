## Delivery contract

1. `npm run skills:package` first checks shared reference sync (never silently repairs stale source) then creates build/kessel-run/ with a self-contained plugin folder named kessel-run containing .codex-plugin/plugin.json and skills/<name>/, and a manifest of exact relative file paths plus SHA-256 content hashes. Package only actual canonical skill dirs and needed references/assets/scripts. No node_modules, .env, user profiles, symlink escapes, databases, private archive or test debris. Reject source symlinks or paths escaping canonical roots. Deterministic order and hashes; no generated current timestamp churn. Before any cleanup/replacement validate output roots against real paths: reject equality/ancestor/descendant overlap with canonical source or plugin template roots, and reject symlinked output ancestors or any escape from the approved build/fixture root. A failed validation must leave sources and symlink targets unchanged. A zip is optional if an available standard command can make one without new dependencies; a validated folder is required.
2. Plugin manifest follows the installed plugin-creator schema. Read /Users/miniying/.codex/skills/.system/plugin-creator/SKILL.md and references/plugin-json-spec.md. Scaffold only into ignored scratch/build to inspect defaults if useful; commit a minimal real manifest with name kessel-run, version0.1.0, description, author.name Kessel Run, skills ./skills/, required interface fields and meaningful starter prompts. No invented license, URLs, MCP servers, apps, or unsupported fields. Author a repo-local distributable template without creating a marketplace (explicit scope overrides default personal installation workflow). Do not claim plugin installation merely from validation.
3. `npm run skills:install:portable -- --destination <explicit dir> [skill names...]` installs canonical skill folders into exactly the explicit skills destination. Resolve CLI/script paths independent of CWD. Allow only existing kessel-run-[a-z0-9-]+ names, validate the entire batch BEFORE mutation, reject traversal/absolute names, reject symlink destinations/unsafe root overlap, no force deletion. Stage copies first, then for each existing installed skill preserve it in a unique dated/nonce backup in a designated backup directory OUTSIDE the explicit skills discovery destination (for example a sibling .kessel-run-skill-backups directory) before replacement. Validate backup/staging roots and their existing ancestors too, including dangling symlinks, before writing any data. Report backup and destination paths. On failure rollback that skill so the original remains available; do not lose user-added reference files. Idempotent unchanged installs should be no-ops. No installed destination chosen implicitly by environment except the explicit legacy wrapper contract below.

Recognize this as Claude-specific installation, not proof of ChatGPT discovery; document a generic Markdown workspace doesn't need CLAUDE.md.
