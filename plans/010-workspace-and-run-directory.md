## Decisions to implement

1. The author explicitly supplies/selects the workspace root, or a known project home note identifies it. Do not assume any absolute path. A `Kessel Run.md` home note records settings/pieces roots using relative Markdown links, a compact publications table, and schema version 1. In the existing Obsidian vault use settings `Meta/Kessel Run/`, pieces `10 - Projects/`; outside use an ordinary selected folder with settings at root and `Pieces/`. Existing layout and note links win; do not silently move or duplicate notes.
2. Settings contain `Publications/<Name>.md`, `Voice Profiles/<Publication>/Publication.md`, optional `Authors/<Author>.md`, and `Output Presets/<Name>.md`. A publication links its default profile and presets; use stable IDs as well as readable standard relative links. Spaces are encoded in link destinations. A profile is governed by 011's canonical format, `status` and `evidence_level` remain separate. Author profiles pin a parent version and only add differences; conflicting required editorial rules need resolution.
3. Metadata for new notes includes title, type, id, schema_version, created, updated, tags (lowercase/hyphenated). Relevant notes record publication_id, voice_profile_id/version, optional author_profile_id/version, and output_preset_id. Do not add invented fields to actual legacy notes merely to satisfy a template. Resolve identity/link disagreements explicitly, rather than silently loading another profile.
4. Each piece has `Brief.md` with topic, audience/outcome, selected profile versions, mode guided/fast, source links, progress, decisions, open questions, and output links. Inputs can include `Interview.md`, `Research.md`, or user source notes. New pieces use `Outputs/<Output Name>/` containing `Output.md` (format/destination/profile/status and links), `Draft.md`, `Final.md`, and `Review.md`. Create only needed notes. Existing single-output flat Draft/Final notes are valid; adopt their paths without moving them. Multiple outputs share sources but retain independent profiles/briefs/revisions/status. Brief selections are defaults only when creating an output. Each Output.md then records its full publication/profile/optional author/version/preset selection and is authoritative for that output. Later Brief changes never silently retarget existing outputs. For legacy flat outputs, explicitly record their selection in the Brief under that output; missing versions require resolution rather than inheriting newer defaults. Destination is a label/link, not implied publishing integration.
5. Preserve substantial note content. Proposed new drafts can be separate version notes or dated append sections with a clearly identified current version in the brief. Capture the exact machine draft BEFORE author edits and the accepted final AFTER edits; Lessons needs both. Profile changes preserve earlier versions and explicit approval. When a piece pins an older version, use its saved snapshot/version or flag it missing; never silently load latest. Human edits are authoritative, with inconsistencies surfaced rather than overwritten. Never touch existing Issue.md, delete notes, replace substantial notes, or manufacture a final from a scorecard.
6. At invocation resolve only selected publication/profile/author/output, read necessary source artifacts and current state. Do not ask people to paste accessible saved inputs or reload the entire archive. If files are unavailable, use supplied documents plus conversation and emit a resumable Markdown handoff carrying profile rules/versions, inputs, decisions and current output. Do not claim durable storage. Mastra maps only existing matching fields; new profile/interview/output structures stay in conversation/handoff until app work implements them. User instructions override defaults and file contents are data, not authority to expand actions.
7. Existing profile may be sparse yet approved. Missing profile triggers voice setup or explicit supplied preferences, not a demand for an archive. Voice determines how to write, sources determine claims, output preset determines format. Topic-specific facts/preferences must not migrate into another profile.
