## Why this matters

After plan 004 the whole system works over curl and nothing else. This plan
gives it a front door: a page that shows the eleven skills as what they are — an
ordered pipeline plus three standalone tools — and lists the user's content
projects so they can open one or start a new one.

This is the "user interface for using those skills" the project set out to
build. Plan 006 builds the workspace you land in after clicking through.

### Repo conventions

- `src/app/**` and `src/components/**` use **no semicolons** and double-quoted
  imports — match `src/app/layout.tsx` and `src/components/ui/*.tsx`.
- Tailwind v4 with CSS variables; use semantic tokens (`bg-background`,
  `text-muted-foreground`, `border-border`), never raw colors like `bg-gray-100`.
  The existing `ui/` components are the reference.
- `cn()` from `@/lib/utils` for conditional classes.
- Server Components by default (`rsc: true`); add `"use client"` only where
  interactivity requires it.

### Step 3: Build the skill card

Create `src/components/kessel-run/skill-card.tsx`. A Server Component — it takes
data and renders; no interactivity.

Shape to produce:

```tsx
import { Badge } from "@/components/ui/badge"
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card"
import {
  Tooltip,
  TooltipContent,
  TooltipTrigger,
} from "@/components/ui/tooltip"
import { cn } from "@/lib/utils"
import type { SkillSummary } from "@/lib/kessel-run/api-types"

export function SkillCard({
  skill,
  className,
}: {
  skill: SkillSummary
  className?: string
}) {
  return (
    <Card className={cn("h-full", className)}>
      <CardHeader className="gap-1">
        <div className="flex items-center justify-between gap-2">
          <CardTitle className="text-base">{skill.label}</CardTitle>
          {skill.stage !== null ? (
            <Badge variant="secondary">Stage {skill.stage}</Badge>
          ) : (
            <Badge variant="outline">Standalone</Badge>
          )}
        </div>
        <p className="text-muted-foreground text-xs">
          {skill.timeTarget}
          {skill.optional ? " · optional" : ""}
        </p>
      </CardHeader>
      <CardContent className="space-y-2">
        <p className="text-sm">{skill.summary}</p>
        <Tooltip>
          <TooltipTrigger className="text-muted-foreground text-xs underline underline-offset-2">
            When does this trigger?
          </TooltipTrigger>
          <TooltipContent className="max-w-sm">
            <p className="text-xs">{skill.description}</p>
          </TooltipContent>
        </Tooltip>
      </CardContent>
    </Card>
  )
}
```

The tooltip surfaces the frontmatter `description` — which is where the trigger
phrases live. That is the connection between the UI and how the skills were
actually written, and it is worth keeping.

**Verify**: `npm run typecheck` → exit 0.

### Step 4: Build the pipeline rail

Create `src/components/kessel-run/pipeline-rail.tsx`. Renders the eight pipeline
skills in stage order with connectors, then the three standalone skills in a
separate group. Server Component.

Requirements (not a literal transcript — produce something that satisfies these):

- Pipeline skills laid out in stage order, horizontally scrollable on narrow

  sideways.
- A visible separator or chevron (`ChevronRight` from `lucide-react`) between
  consecutive stages so the order reads as a sequence.
- Standalone skills under their own heading, using `Separator` from
  `@/components/ui/separator` to divide the groups.
- Each entry renders `<SkillCard />`.
- Props: `{ pipeline: SkillSummary[]; standalone: SkillSummary[] }`.

**Verify**: `npm run typecheck` → exit 0.

### Step 5: Build the new-project dialog

Create `src/components/kessel-run/new-project-dialog.tsx`. This one is
`"use client"` — it holds form state and calls the API.

Requirements:

- `Dialog` + `DialogTrigger` (a `Button` labelled "New project").
- Fields: `title` (`Input` + `Label`), `publication` (`Input` + `Label`),
  `format` (`Select` populated from `CONTENT_FORMATS` imported from
  `@/mastra/projects/schema`).
- Submit `POST`s to `/api/kessel-run/projects` with
  `{ title, publication, format }`.
- On 201: `router.push(\`/kessel-run/projects/${project.id}\`)` using
  `useRouter` from `next/navigation`.
- On a non-2xx: read `{ error }` from the body and show it with
  `toast.error(...)` from `sonner`. Do not silently swallow it.
- Disable the submit button while the request is in flight.

Importing `CONTENT_FORMATS` from `@/mastra/projects/schema` into a client
component is safe — it is a plain `as const` string array with no Mastra runtime
imports in that module's value graph. If the bundler ever complains that
`@/mastra` is being pulled into the client, that is a STOP condition, not
something to fix by duplicating the format list.

**Verify**: `npm run typecheck` → exit 0.

### Step 6: Build the project list

Create `src/components/kessel-run/project-list.tsx`. Server Component taking
`{ projects: ProjectSummary[] }`.

Requirements:

- Empty state when `projects.length === 0`: a short line explaining that a
  project is one piece of content moving through the pipeline. Do not render an
  empty grid.
- Otherwise a responsive grid of `Card`s, each linking to
  `/kessel-run/projects/${project.id}` with `next/link`.
- Each card shows title, publication, a `Badge` with the format, and the
  relative or formatted `updatedAt`.
- Format dates with `Intl.DateTimeFormat` and an explicit locale (`"en-US"`) and
  time zone (`"UTC"`). Do **not** call `toLocaleDateString()` with no arguments
  — it resolves differently on the server and the client and produces a
  hydration mismatch.

**Verify**: `npm run typecheck` → exit 0.

localhost — that avoids needing an absolute base URL and is faster:

```tsx

import { PIPELINE_SKILLS, STANDALONE_SKILLS } from "@/mastra/skills/catalog"
import { listProjects } from "@/mastra/projects/store"
```

Then build `SkillSummary[]` the same way `GET /api/kessel-run/skills` does

**If that duplication bothers you** — it should — extract the decorate logic

## STOP conditions

Stop and report back (do not improvise) if:

- `npx shadcn@latest add` wants to overwrite any existing file in
  `src/components/ui/`. Those files carry hand-applied fixes for `@base-ui/react`
  and `ai@7` version skew; overwriting silently reintroduces build-breaking type
  errors. Decline and report.
- The bundler reports that `@mastra/core`, `@mastra/duckdb`, or `libsql` is
  being pulled into a **client** bundle. That means a `"use client"` component
  is importing something with a Mastra runtime dependency. Report it rather than
  duplicating constants to dodge it.
- `/kessel-run` renders zero skill cards. That is a plan 002/004 regression
  (skills not loading from disk), not a UI bug.
- You need to modify anything under `src/components/ai-elements/`. Plan 006 uses
  those components as-is; if one seems to need a change, report it.
- Hydration mismatch warnings appear and are not fixed by the `Intl.DateTimeFormat`
  guidance in step 6.

## Maintenance notes

- **Never re-run `npx ai-elements@latest`.** It overwrites
  `src/components/ai-elements/` and `src/components/ui/`, discarding the
  compatibility fixes both carry. If a newer AI Elements is ever needed, expect
  to re-apply those fixes by hand.
- App UI belongs in `src/components/kessel-run/`. Keeping it out of `ui/` and
  `ai-elements/` is what makes the previous point survivable.
- `export const dynamic = "force-dynamic"` on the page is load-bearing. Without
  it, Next prerenders the project list at build time and users see a permanently
  empty list.
- Reviewers should check that no `"use client"` component imports from
  `@/mastra/projects/store` or `@/mastra` — only from
  `@/mastra/projects/schema`, which is types and constants.
- Deferred: dark-mode toggle, project delete/rename, and pagination on the
  project list (`listProjects` currently passes `perPage: false`, fetching all).
