## Required behavior

1. Start has a concise trigger for starting/resuming a piece or choosing the next writing action. Read selected workspace home/Brief/output first, follow explicit profile and parent links with pinned versions. Missing topic/publication/profile choices are asked conversationally; never infer the desired voice from the account owner's prose. Resume without re-asking known answers. For new publication create/use a sparse voice setup via kessel-run-voice when available; instruction should remain usable if the sibling is not installed by asking for explicit preferences and returning a handoff.
2. The user chooses an output format and optional author. Reuse existing publication/preset defaults. Choose guided by default; user can request fast. Record mode, sources, missing information and next step. Skip stages whose results are supplied or unnecessary for the format. Short posts do not require a full ideation map/beat map. Create only necessary brief/output notes through the workspace contract, not an empty folder tree.
3. For substantive author experiences interview only missing material, one question at a time; preserve raw answers as evidence without equating speaking style to desired writing voice. Start and Interview should not demand two stories or a contrarian stance for every review/post. Format and editorial purpose govern sufficiency. Research uses real retrieval only when tools are available; otherwise operate on supplied sources and label coverage limitations, never simulate searches.
4. Draft uses voice profile + sources + output brief. Author preferences and approved sparse profiles are valid. Guided mode collaboratively drafts sections; fast mode drafts a complete coherent piece from adequate material and reports missing facts/decisions afterward. Fast mode doesn't invent gaps or silently change the thesis. Existing absolute prohibitions against full-draft generation must be reconciled throughout, not merely overridden by one new paragraph.
5. Source discipline applies to every factual/personal claim, including hooks, transitions and endings. Sources can be transcript answers, supplied notes, documented testing, or attributed research. Style samples do not transfer facts. Framing and connective language with no new claim can be authored. Missing details become explicit placeholders; avoid numeric 'sourcing ratios' that reward forced quotes rather than accurate evidence. Surface genuine gaps without obstructing all writing. Never add first-person testing/experience because a review profile calls for confidence.
6. Personalize/Polish check the selected publication/author voice instead of pushing every output to sound like the account owner. Parent editorial constraints and author differences remain distinguishable. Keep review notes/scorecards separate from prose. Preserve machine-produced draft snapshot before user edits and accepted Final afterwards. A user can accept imperfect prose; don't label it fact-verified merely because style is good. Do not publish as part of completion.
7. Repurpose creates each rendition as its own output with explicit format/profile references, independent revisions and status. Reuse source material, not stale unsupported claims. Cross-publication output resolves the target voice deliberately; it does not migrate the original profile's lessons. Never overwrite original final to produce a rendition.
8. Current app stage numbers 0..7 remain. Interview, Start, Voice, Review, Repurpose, Analyze stay standalone; docs describe alternate routes by names instead of pretending all stages are required. Remove nonexistent numbered Review/Repurpose/Distribute promises. App with no filesystem keeps current matching memory fields and returns handoff for extra artifacts; no invented persistent profile/output fields.
