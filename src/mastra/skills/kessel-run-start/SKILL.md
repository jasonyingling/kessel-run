# Kessel Run — Start / Resume

Help the author reach the next useful writing action without repeating setup or forcing a full pipeline.

## Workspace context

Before starting, read [the shared workspace contract](references/workspace.md) to locate the selected publication, exact voice versions, output and sources, preserve existing notes, and provide a resumable handoff when files are unavailable.

Use the output's selected publication voice and optional author overlay at their pinned versions; keep parent editorial requirements distinct from author differences. Approved sparse profiles or explicit supplied preferences are sufficient. Do not default to the account owner's voice. Ask only for unresolved choices after reading accessible state. Preserve human edits, exact machine drafts and accepted finals as described in the workspace contract.

Use the Brief/output's mode: guided by default, fast when requested. Reuse supplied work and skip unnecessary stages; numbered stages describe available methods, not mandatory gates. All factual and personal claims, including hooks, transitions and endings, need source support from interviews, notes, testing records or attributed research. Profile examples supply style, not new facts. Claim-free connective language is allowed. Use specific placeholders for missing facts and report gaps without blocking supported writing. A confident voice never licenses invented use, tests, results or certainty, or attributing an unexpressed opinion to the author. Supported editorial analysis and provisional recommendations may be proposed with reasoning; label inference rather than presenting it as observed fact. Keep scorecards outside prose; acceptance is not fact verification or publishing authorization.

## Resolve the current work

Read the known home note, selected Brief and output state first. Identify the topic, publication, output format, optional author and exact profile snapshots (including the author's pinned parent). Existing output selections take precedence over changed publication/Brief defaults. If multiple pieces or outputs match, ask which one; never silently retarget one. Check sources and current draft before asking for information already available.

For new work, use an explicitly named publication and its defaults; ask conversationally for only missing topic, publication/voice or consequential output choices. Reuse the selected output preset. Do not infer voice rules from a publication name or the user's speaking style. With no profile, offer Voice setup if that skill is available; otherwise ask for a few intended writing preferences and retain them in the brief/handoff as provisional guidance. No archive is required, and approved sparse profiles are valid.

Record mode (guided unless fast requested), selections, source links/provenance, gaps, decisions, progress and next step in the workspace. Create only needed notes. Existing output-specific voice selections and revisions remain independent when another output is added.

## Choose the next useful action

- **Voice** establishes or refines writing guidance when needed; it is separate from interviewing for source material.
- **Anchor** resolves missing topic, audience or outcome. Reuse an existing anchor.
- **Interview** gathers missing substantive material with one question at a time. Supplied notes or research can make it unnecessary.
- **Research** fills evidence gaps with actual available retrieval tools, or organizes supplied sources with limitations.
- **Ideation / Hook / Architecture** develop only what the piece lacks. A short post may need one point and a direct opening, not separate maps.
- **Draft** turns adequate sources and the brief into prose. Guided mode collaborates section by section; fast mode produces a complete coherent draft with unresolved facts marked.
- **Personalize / Polish** align the selected voice and improve the existing prose without replacing human edits or manufacturing acceptance.
- **Repurpose** creates another independent output. **Review** audits existing content for freshness. **Analyze** interprets supplied performance evidence.

Use an available skill by name when appropriate. If a sibling skill is absent, continue the bounded next action using the selected voice, evidence and user intent, or give a concrete handoff; do not claim unavailable tools ran. Do not change the thesis or invent sources to keep moving. In guided mode respect a pending section decision; in fast mode do not insert repeated section approvals. Ask only where missing information materially affects the work.

## Pause and resume

At a pause, record the actual current draft, completed actions, next action and open decisions alongside full output selection IDs/versions. With no files, emit the workspace handoff containing actual rules (including parent and author differences), relevant inputs/provenance and current output prose, not just inaccessible links. Name anything missing and never claim a file was saved. In legacy demo projects, use only existing matching working-memory fields; additional structures stay in conversation/handoff. In the local writing app, use the shared content operations described in the runtime capability guide below.

## App runtime capabilities

When working in the local app or through MCP, read [the runtime capability guide](references/app-runtime.md). Use only available capabilities; keep these editorial methods and the portable handoff unchanged.
