# Kessel Run — Stage 5: Draft

Write from the selected voice, source material and output brief. Keep the author in control of the thesis and their existing edits.

## Workspace context

Before starting, read [the shared workspace contract](references/workspace.md) to locate the selected publication, exact voice versions, output and sources, preserve existing notes, and provide a resumable handoff when files are unavailable.

Use the output's selected publication voice and optional author overlay at their pinned versions; keep parent editorial requirements distinct from author differences. Approved sparse profiles or explicit supplied preferences are sufficient. Do not default to the account owner's voice. Ask only for unresolved choices after reading accessible state. Preserve human edits, exact machine drafts and accepted finals as described in the workspace contract.

Use the Brief/output's mode: guided by default, fast when requested. Reuse supplied work and skip unnecessary stages; numbered stages describe available methods, not mandatory gates. All factual and personal claims, including hooks, transitions and endings, need source support from interviews, notes, testing records or attributed research. Profile examples supply style, not new facts. Claim-free connective language is allowed. Use specific placeholders for missing facts and report gaps without blocking supported writing. A confident voice never licenses invented use, tests, results or certainty, or attributing an unexpressed opinion to the author. Supported editorial analysis and provisional recommendations may be proposed with reasoning; label inference rather than presenting it as observed fact. Keep scorecards outside prose; acceptance is not fact verification or publishing authorization.

## Inputs and voice

Read the current draft and source notes. Use an approved outline, ideation map or hook if supplied; otherwise form a proportionate structure from the brief. A short post does not need a separate beat map. Ask only when topic, intended outcome or consequential direction is missing; report evidence gaps locally instead of demanding every planning artifact.

Apply supported Tone and Rhythm, Use/Avoid rules, format variations and author differences. Approved examples calibrate phrasing but do not supply facts for this piece. Sparse dimensions remain unspecified. If a style rule asks for concrete numbers and no number exists, use a placeholder or a supported qualitative statement. If the voice favors confidence, retain necessary uncertainty and attribution. Editorial requirements prevail over conflicting author differences after the conflict is surfaced for resolution.

Use signature devices where they help, not in every paragraph. Compare the draft with the selected rules rather than an imagined universal authentic voice. Explicit edits guide this piece; inferred reusable lessons require separate profile-scoped confirmation.

## Guided mode

Start with an existing approved opening or draft the first useful section. Briefly identify its purpose, then present clean prose with any factual placeholders visible. Keep commentary about voice and gaps separate.

Pause after each meaningful section for the author's approval or edits before drafting the next. A short post can be one section. On resume, honor already approved sections and the currently pending decision. Use actual edited endings when building transitions; do not restore removed claims. If feedback is clear, apply it without asking the user to repeat it.

Track length and repetition across sections. The sequence should build understanding rather than repeat the thesis. Use available stories, evidence, contrasts and pivots according to purpose; sensory details, emotions and results require sources too. End with the selected outcome, not an automatic CTA.

## Fast mode

When requested, write a complete coherent draft from adequate supplied material without section approval stops. Reuse confirmed structure, or choose a lightweight structure that serves the brief. Do not silently change the thesis. Unsupported details stay as explicit placeholders such as `[FACT NEEDED: measured battery runtime and test conditions]`; omit nonessential missing claims where possible. Report unresolved decisions and limitations outside the prose. Fast does not mean approved or ready to publish.

## Preserve and deliver

Before editing existing material, keep its current version and capture exact machine prose separately from human edits according to the workspace contract. Never overwrite a substantial draft. Save or return the new Draft and current-version link with source references, remaining gaps, selection IDs/versions and next action. Use citations or an accompanying claim/source map appropriate to the preset so claims remain traceable without cluttering every sentence.

In guided mode compile approved sections when complete; in fast mode present the full draft immediately. A later accepted Final is a separate record of the actual accepted prose. Suggest Personalize or Polish only when useful. Do not infer final acceptance from a quality score.
