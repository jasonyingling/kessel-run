# Kessel Run Content Pipeline — Complete Skills Package

This package contains all 11 skills that make up the Kessel Run content pipeline — a structured system for creating high-quality, authentic content from research through publication and analysis.

## What is Kessel Run?

Kessel Run is a 10-stage content creation system designed to move content from raw idea to published, analyzed piece. Each stage has a specific purpose, and the stages build on each other. The system balances AI assistance with human creativity and authenticity.

## Pipeline Overview

### Stage 0: Research
**File**: `06-research.md`

Deep research on a topic before content creation begins. Maps the landscape, identifies content gaps, and produces a research brief that feeds directly into the Anchor stage.

**Trigger phrases**: "I want to research," "help me understand the space," "find me data on"

---

### Stage 1: Anchor
**File**: `01-anchor.md`

Defines the foundation for any piece of content. Locks in the topic, audience, publication, format, goal, and framing before writing begins.

**Trigger phrases**: "I have an idea for a post," "help me plan content about," "what angle should I take"

---

### Stage 2: Ideation
**File**: `02-ideation.md`

Expands the anchor into a full ideation map with thesis, supporting angles, counterarguments, story beats, and evidence inventory. This is where the substance of the piece gets developed.

**Trigger phrases**: "help me develop this idea," "what angles should I cover," "I need to flesh this out"

---

### Stage 3: Hook
**File**: `03-hook.md`

Generates multiple opening hooks across different archetypes and helps the user select and refine the strongest one. The hook earns the reader's first 10 seconds.

**Trigger phrases**: "I need a hook," "how should I open this," "help me with the opening"

---

### Stage 4: Architecture
**File**: `04-architecture.md`

Creates the structural blueprint for the piece. Produces a beat-by-beat map that includes section purpose, energy levels, transitions, and strategies for sustaining reader attention.

**Trigger phrases**: "help me outline this," "what structure should this take," "help me with the flow"

---

### Stage 5: Draft
**File**: `05-draft.md`

Writes the piece section by section following the beat map, in the publication's voice, using the user's own material. This is AI-assisted but user-controlled — each section is reviewed before the next is drafted.

**Trigger phrases**: "let's start writing," "draft this piece," "I'm ready to write"

---

### Stage 6: Personalize
**File**: `09-personalize.md`

Audits the draft for authenticity and prompts the user to inject personal details, opinions, and specific experiences that make the content unmistakably theirs.

**Trigger phrases**: "this sounds too generic," "make it sound more like me," "it needs more personality"

---

### Stage 7: Polish
**File**: `10-polish.md`

Final quality control before publishing. Evaluates the piece across seven dimensions (readability, redundancy, hook strength, closing strength, promise delivery, coherence, format compliance) and provides a scorecard with specific fixes.

**Trigger phrases**: "is this ready to publish," "final review," "how does this look overall"

---

### Stage 8: Review (Standalone Skill)
**File**: `07-review.md`

Audits published content for continued accuracy, relevance, and voice consistency over time. Helps identify what needs updating, refreshing, or retiring.

**Trigger phrases**: "is this still accurate," "should I update this post," "content audit"

---

### Stage 9: Repurpose (Standalone Skill)
**File**: `08-repurpose.md`

Adapts existing content into other formats (LinkedIn posts, threads, newsletters, video scripts, etc.). Works with content from the pipeline or any other source.

**Trigger phrases**: "turn this into a LinkedIn post," "make a thread from this," "repurpose this"

---

### Stage 10: Analyze (Standalone Skill)
**File**: `11-analyze.md`

Post-publish analysis of content performance against original goals. Extracts lessons for future content and builds a feedback loop from the end of the pipeline back to the beginning.

**Trigger phrases**: "how did my post do," "analyze this piece," "what can I learn from this"

---

## How to Use This Package

### For Individual Pieces
Use these skills sequentially when creating a new piece:
1. Research (Stage 0) — optional, but recommended
2. Anchor (Stage 1)
3. Ideation (Stage 2)
4. Hook (Stage 3)
5. Architecture (Stage 4)
6. Draft (Stage 5)
7. Personalize (Stage 6)
8. Polish (Stage 7)

### For Standalone Tasks
Use these skills independently:
- **Review** — For auditing existing published content
- **Repurpose** — For adapting content across formats
- **Analyze** — For evaluating published piece performance

### Typical Workflow

**For a new article or blog post:**
Anchor → Ideation → Hook → Architecture → Draft → Personalize → Polish

**For a new LinkedIn post:**
Anchor (brief) → Ideation (lightweight) → Hook → Draft (abbreviated) → Personalize

**For a newsletter edition:**
Research → Anchor → Ideation → Draft → Personalize → Polish

**For existing published content:**
Review → Analyze (if performance data available)

**For cross-format distribution:**
Repurpose (from any published piece to other formats)

## Key Principles Across All Stages

**Speed with substance.** Each stage has time targets to keep momentum. A good-enough decision that moves forward beats a perfect decision that stalls.

**The user drives.** Stages suggest, generate options, and prompt. But the user decides. AI assists; humans author.

**Specificity is the skill.** Every stage pushes toward concrete details over generic claims. "I built this app in 12 hours with Claude" is infinitely better than "AI is changing development."

**No inventing.** AI-generated placeholder fills, fabricated statistics, or invented personal experiences have no place in content. Honest placeholders beat fake details.

**Voice profiles shape everything.** A publication's voice profile (patterns, anti-patterns, signature moves) is applied at every stage from Hook onward.
